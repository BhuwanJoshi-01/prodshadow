# PS104 · add-column-not-null-without-default

| Default severity | Evidence |
|---|---|
| warning | static |

## What it detects

`ADD COLUMN ... NOT NULL` without a default, identity or generated expression on a pre-existing table.

## Why it matters

Existing rows would receive `NULL`, which violates the constraint, so the statement fails with `23502 not_null_violation` on any table that has rows. In development the table is often empty, so the failure only shows up in production.

## Example

Flagged:

```sql
ALTER TABLE orders ADD COLUMN region text NOT NULL;
```

Preferred:

```sql
ALTER TABLE orders ADD COLUMN region text;
-- backfill region in batches, then:
ALTER TABLE orders ADD CONSTRAINT orders_region_not_null CHECK (region IS NOT NULL) NOT VALID;
ALTER TABLE orders VALIDATE CONSTRAINT orders_region_not_null;
ALTER TABLE orders ALTER COLUMN region SET NOT NULL;
```

## How ProdShadow verifies it

With a non-empty fixture the candidate run fails and `OBS003` reports SQLSTATE `23502` at the statement's line.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS104: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS104 reason="why this is acceptable" expires=2027-06-30
```
