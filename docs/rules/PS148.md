# PS148 · invalid-annotation

| Default severity | Evidence |
|---|---|
| warning | static |

## What it detects

A `-- prodshadow:` comment above a statement that cannot be used: an unknown directive (for example a misspelled `ignore`), `ignore` without a rule ID or without `reason="..."`, a malformed rule ID, or an `expires` date that is not `YYYY-MM-DD`.

## Why it matters

Invalid directives are ignored. Without this rule, a suppression with a typo silently does not apply, and the finding it was meant to excuse shows up again with no hint why; or the directive is never noticed at all. Reporting it points at the comment to fix.

## Example

Flagged:

```sql
-- prodshadow:ignore PS101
CREATE INDEX countries_name_idx ON countries (name);
```

Preferred:

```sql
-- prodshadow:ignore PS101 reason="lookup table with 40 rows" expires=2027-01-31
CREATE INDEX countries_name_idx ON countries (name);
```

## How ProdShadow verifies it

Static only.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS148: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS148 reason="why this is acceptable" expires=2027-06-30
```
