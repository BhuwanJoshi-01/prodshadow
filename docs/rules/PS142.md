# PS142 · autovacuum-disabled

| Default severity | Evidence |
|---|---|
| warning | static |

## What it detects

`ALTER TABLE ... SET (autovacuum_enabled = false)`, the `toast.` variant, and `CREATE TABLE ... WITH (autovacuum_enabled = false)`.

## Why it matters

With autovacuum off for a table, dead rows from updates and deletes are no longer cleaned up and statistics go stale, so the table and its indexes bloat and plans get worse. PostgreSQL still forces an anti-wraparound vacuum when transaction IDs age, but by then it runs on a large, bloated table at an unplanned time. Disabling autovacuum for a bulk load is sometimes reasonable; leaving it disabled after the migration rarely is.

## Example

Flagged:

```sql
ALTER TABLE events SET (autovacuum_enabled = false);
```

Preferred:

```sql
-- tune instead of disabling\nALTER TABLE events SET (autovacuum_vacuum_scale_factor = 0.01, autovacuum_vacuum_cost_delay = 2);
```

## How ProdShadow verifies it

Static only.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS142: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS142 reason="why this is acceptable" expires=2027-06-30
```
