# PS118 · trigger-change-blocks-writes

| Default severity | Evidence |
|---|---|
| info | static |

## What it detects

`CREATE TRIGGER` and `ALTER TABLE ... ENABLE/DISABLE TRIGGER` on a pre-existing table.

## Why it matters

These take `SHARE ROW EXCLUSIVE`, which waits for in-flight writes and blocks new writes until the transaction commits. The statement itself is quick, but it can queue behind long transactions.

## Example

Flagged:

```sql
CREATE TRIGGER orders_audit AFTER UPDATE ON orders
  FOR EACH ROW EXECUTE FUNCTION audit();
```

Preferred:

```sql
SET lock_timeout = '2s';
CREATE TRIGGER orders_audit AFTER UPDATE ON orders
  FOR EACH ROW EXECUTE FUNCTION audit();
```

## How ProdShadow verifies it

Write scenarios show any wait in the candidate run.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS118: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS118 reason="why this is acceptable" expires=2027-06-30
```
