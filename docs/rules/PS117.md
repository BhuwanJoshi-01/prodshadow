# PS117 · procedural-code

| Default severity | Evidence |
|---|---|
| info | experiment quality |

## What it detects

`DO` blocks and `CALL` statements.

## Why it matters

Procedural code can run any statement, so its locks cannot be predicted from the SQL text. Only the experiment shows what it does.

## Example

Flagged:

```sql
DO $$ BEGIN EXECUTE 'ALTER TABLE ' || 'orders' || ' ADD COLUMN x int'; END $$;
```

Preferred:

```sql
-- prefer plain SQL migrations where possible
ALTER TABLE orders ADD COLUMN x int;
```

## How ProdShadow verifies it

The candidate run measures the procedure's real effect on the workload.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS117: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS117 reason="why this is acceptable" expires=2027-06-30
```
