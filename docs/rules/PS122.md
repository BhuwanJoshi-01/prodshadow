# PS122 · drop-index-blocks-traffic

| Default severity | Evidence |
|---|---|
| warning | static |

## What it detects

`DROP INDEX` without `CONCURRENTLY`.

## Why it matters

Dropping an index takes `ACCESS EXCLUSIVE` on the table that owns it. The drop is quick, but the request queues behind long transactions and blocks all reads and writes on the table while it waits.

## Example

Flagged:

```sql
DROP INDEX orders_status_idx;
```

Preferred:

```sql
DROP INDEX CONCURRENTLY orders_status_idx;  -- outside a transaction block
```

## How ProdShadow verifies it

With a background session on the table, the candidate run shows the queue.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS122: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS122 reason="why this is acceptable" expires=2027-06-30
```
