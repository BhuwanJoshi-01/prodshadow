# OBS008 · throughput-drop

| Default severity | Evidence |
|---|---|
| critical | observed |

## What it detects

A scenario's median throughput fell by more than `policy.max_throughput_drop_pct`, evaluated only when that budget is set.

## Why it matters

In closed-loop workloads a stall shows up as fewer completed operations; this budget catches broad slowdowns that latency percentiles average away.

## Example

Flagged:

```yaml
policy:
  max_throughput_drop_pct: 5
```

Preferred:

```yaml
policy:
  max_throughput_drop_pct: 25   # tolerate short migration windows
```

## How ProdShadow verifies it

Throughput is measured over the whole candidate window, which includes time before and after the migration, so short stalls are diluted.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    OBS008: critical   # or info, warning, off
```

Suppress a reviewed case in the suppressions file (`policy.suppressions`):

```yaml
version: 1
suppressions:
  - rule: OBS008
    reason: "why this is acceptable"
    expires: 2027-06-30
```
