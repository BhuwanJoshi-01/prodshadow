# PS155 · not-rerunnable

| Default severity | Evidence |
|---|---|
| info | static |

## What it detects

In a migration file that is not executed as one transaction (because it contains statements such as `CREATE INDEX CONCURRENTLY`, or `migration.transaction` is `none`), the first statement before the end of the file that creates an index, table, sequence or column without `IF NOT EXISTS`.

## Why it matters

Each statement of such a file commits on its own. If a later statement fails, the earlier ones stay applied, and most migration tools then run the whole file again on the next deploy, which fails at the first object that already exists. A failed concurrent index build also leaves an invalid index behind (see [PS121](PS121.md) and [PS132](PS132.md)).

## Example

Flagged:

```sql
CREATE INDEX CONCURRENTLY orders_status_idx ON orders (status);
CREATE INDEX CONCURRENTLY orders_created_idx ON orders (created_at);
```

Preferred:

```sql
DROP INDEX CONCURRENTLY IF EXISTS orders_status_idx;
CREATE INDEX CONCURRENTLY IF NOT EXISTS orders_status_idx ON orders (status);
-- or put each concurrent build in a migration file of its own
```

## How ProdShadow verifies it

Static only.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS155: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS155 reason="why this is acceptable" expires=2027-06-30
```
