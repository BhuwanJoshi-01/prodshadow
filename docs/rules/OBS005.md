# OBS005 · p95-latency-regression

| Default severity | Evidence |
|---|---|
| critical | observed |

## What it detects

A scenario's candidate p95 latency (median across repeats) divided by its baseline p95 exceeds `policy.max_p95_latency_ratio` (default 1.5) **and** exceeds the noise band `1 + 3 × CV`, where CV is the coefficient of variation of the baseline p95 across repeats.

## Why it matters

A migration can slow traffic without blocking it: an added trigger, a lost index, a rewrite that evicts the cache, or an error storm from stale clients. Within the noise band, or when the baseline varies by more than 50 %, the finding is `inconclusive` instead of `critical`, because the change cannot be told apart from runner noise.

## Example

Flagged:

```yaml
policy:
  max_p95_latency_ratio: 1.5
```

Preferred:

```yaml
policy:
  max_p95_latency_ratio: 2.0   # for noisy shared runners
  max_p99_latency_ratio: 3.0   # optional tail budget (OBS006)
```

## How ProdShadow verifies it

Confidence is high with at least three repeats and baseline noise below 20 %.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    OBS005: critical   # or info, warning, off
```

Suppress a reviewed case in the suppressions file (`policy.suppressions`):

```yaml
version: 1
suppressions:
  - rule: OBS005
    reason: "why this is acceptable"
    expires: 2027-06-30
```
