# PS139 · plaintext-password

| Default severity | Evidence |
|---|---|
| warning | static |

## What it detects

`CREATE ROLE`/`CREATE USER`/`ALTER ROLE` with `PASSWORD '...'`, and `CREATE`/`ALTER USER MAPPING` with a `password` option, when the value is a plain-text password. `PASSWORD NULL` and stored hashes (SCRAM verifiers, `md5` hashes) are not reported. The finding never repeats the value.

## Why it matters

Migration files are committed to version control, copied into CI workspaces and printed in deploy logs. A password written in one is readable by everyone with access to any of those, and stays in the repository history after the password is rotated. ProdShadow redacts these values from its reports, but it cannot remove them from your repository.

## Example

Flagged:

```sql
CREATE ROLE reporting LOGIN PASSWORD 'correct-horse-battery';
```

Preferred:

```sql
CREATE ROLE reporting LOGIN;
-- set the password from the secrets manager at deploy time, e.g.
-- psql -c "\password reporting" (sends a SCRAM verifier, not the password)
```

## How ProdShadow verifies it

Static only.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS139: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS139 reason="why this is acceptable" expires=2027-06-30
```
