# PS150 · unused-annotation

| Default severity | Evidence |
|---|---|
| info | static |

## What it detects

A valid, unexpired `-- prodshadow:ignore` directive that names a static (`PS`) rule which reports nothing for the statement below it, not even a suppressed finding. Observed and quality rules are not checked, because they are only evaluated after the experiment.

## Why it matters

Suppressions outlive the problems they excuse: the statement gets fixed, or the rule ID was mistyped (`PS110` for `PS101`). A leftover directive hides a future finding of that rule on the same statement without anyone reviewing it. Removing unused directives keeps every suppression meaningful.

## Example

Flagged:

```sql
-- prodshadow:ignore PS101 reason="lookup table with 40 rows"
CREATE INDEX CONCURRENTLY countries_name_idx ON countries (name);
```

Preferred:

```sql
CREATE INDEX CONCURRENTLY countries_name_idx ON countries (name);
```

## How ProdShadow verifies it

Static only.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS150: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS150 reason="why this is acceptable" expires=2027-06-30
```
