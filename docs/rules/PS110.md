# PS110 · rename-breaks-running-code

| Default severity | Evidence |
|---|---|
| warning | static |

## What it detects

`ALTER TABLE ... RENAME TO` and `ALTER TABLE ... RENAME COLUMN`.

## Why it matters

The rename is instant, but every running application instance that still uses the old name fails immediately, and keeps failing until all instances are replaced.

## Example

Flagged:

```sql
ALTER TABLE orders RENAME COLUMN note TO memo;
```

Preferred:

```sql
ALTER TABLE orders ADD COLUMN memo text;
-- write both columns, backfill, move readers to memo,
-- then drop note in a later release
```

## How ProdShadow verifies it

Model the old release's queries in the workload; their failures appear as `OBS007` with the `undefined_object` error class.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS110: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS110 reason="why this is acceptable" expires=2027-06-30
```
