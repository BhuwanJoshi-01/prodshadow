# PS152 · int-primary-key

| Default severity | Evidence |
|---|---|
| info | heuristic |

## What it detects

`CREATE TABLE` (not temporary) whose single-column primary key is `integer`, `smallint`, `serial` or `smallserial`, including identity columns of those types.

## Why it matters

An `integer` key holds at most 2,147,483,647 values and `smallint` 32,767. Sequences also skip values (rolled-back inserts, cached sequence values, `ON CONFLICT` upserts), so a busy table can run out years before it has that many rows, and inserts then fail. Changing the type later rewrites the table and every table with a foreign key to it, under `ACCESS EXCLUSIVE` — one of the most disruptive migrations there is. `bigint` costs four extra bytes per row. Small, bounded lookup tables are fine, which is why this is information.

## Example

Flagged:

```sql
CREATE TABLE events (
  id serial PRIMARY KEY,
  payload jsonb NOT NULL
);
```

Preferred:

```sql
CREATE TABLE events (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  payload jsonb NOT NULL
);
```

## How ProdShadow verifies it

Static only.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS152: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS152 reason="why this is acceptable" expires=2027-06-30
```
