# PS147 · replica-identity-change

| Default severity | Evidence |
|---|---|
| warning | heuristic |

## What it detects

`ALTER TABLE ... REPLICA IDENTITY NOTHING` and `ALTER TABLE ... REPLICA IDENTITY FULL` on a table that existed before the migration.

## Why it matters

The replica identity is what logical replication and change data capture (Debezium, publications to other databases) use to identify the old row of an update or delete. With `NOTHING`, PostgreSQL refuses `UPDATE` and `DELETE` on a table that belongs to a publication publishing them, so the application's writes start failing. With `FULL`, every update and delete writes the entire old row to the WAL, which can multiply WAL volume and replication lag on a busy table. Whether the table is published is not visible in the migration, so the finding is a heuristic.

## Example

Flagged:

```sql
ALTER TABLE orders REPLICA IDENTITY NOTHING;
```

Preferred:

```sql
-- keep the default (primary key), or name a unique, non-null index\nALTER TABLE orders REPLICA IDENTITY USING INDEX orders_reference_key;
```

## How ProdShadow verifies it

Static only: the disposable server has no publications.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS147: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS147 reason="why this is acceptable" expires=2027-06-30
```
