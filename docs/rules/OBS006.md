# OBS006 · p99-latency-regression

| Default severity | Evidence |
|---|---|
| critical | observed |

## What it detects

Like `OBS005`, for the p99 latency, evaluated only when `policy.max_p99_latency_ratio` is set.

## Why it matters

Tail latency reacts first to short lock waits and contention. p99 needs more samples than p95 to be stable; keep `workload.min_samples_per_scenario` high enough.

## Example

Flagged:

```yaml
policy:
  max_p99_latency_ratio: 1.5
```

Preferred:

```yaml
policy:
  max_p99_latency_ratio: 3.0
workload:
  min_samples_per_scenario: 1000
```

## How ProdShadow verifies it

The same noise band as `OBS005` applies.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    OBS006: critical   # or info, warning, off
```

Suppress a reviewed case in the suppressions file (`policy.suppressions`):

```yaml
version: 1
suppressions:
  - rule: OBS006
    reason: "why this is acceptable"
    expires: 2027-06-30
```
