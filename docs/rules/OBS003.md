# OBS003 · migration-failed

| Default severity | Evidence |
|---|---|
| critical | observed |

## What it detects

A migration statement failed in the disposable database for any reason other than a lock or statement timeout. The finding reports the SQLSTATE and the (redacted) server message at the statement's file and line.

## Why it matters

The same statement fails in production. Common causes: `NOT NULL` additions on populated tables (`23502`), duplicate values for a new unique constraint (`23505`), objects missing from the fixture (`42P01`), and statements that cannot run in a transaction block (`25001`).

## Example

Flagged:

```sql
ALTER TABLE orders ADD COLUMN region text NOT NULL;
```

Preferred:

```sql
ALTER TABLE orders ADD COLUMN region text;
```

## How ProdShadow verifies it

Statements after the failing one are reported as skipped; earlier statements of the same transaction are reported as rolled back.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    OBS003: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore OBS003 reason="why this is acceptable" expires=2027-06-30
```
