# PS108 · unique-constraint-builds-index

| Default severity | Evidence |
|---|---|
| warning | static |

## What it detects

`ADD CONSTRAINT ... UNIQUE`, `ADD PRIMARY KEY` or `ADD CONSTRAINT ... EXCLUDE` without `USING INDEX`, and `ADD COLUMN ... UNIQUE` or `ADD COLUMN ... PRIMARY KEY`, which build their index the same way.

## Why it matters

The constraint's index is built while `ACCESS EXCLUSIVE` is held, so all reads and writes wait for the full index build.

## Example

Flagged:

```sql
ALTER TABLE orders ADD CONSTRAINT orders_ref_key UNIQUE (ref);
```

Preferred:

```sql
CREATE UNIQUE INDEX CONCURRENTLY orders_ref_key ON orders (ref);
ALTER TABLE orders ADD CONSTRAINT orders_ref_key UNIQUE USING INDEX orders_ref_key;
```

## How ProdShadow verifies it

The candidate run shows reads and writes stalling for the build duration.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS108: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS108 reason="why this is acceptable" expires=2027-06-30
```
