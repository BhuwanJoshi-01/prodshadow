# PS113 · rewrite-under-exclusive-lock

| Default severity | Evidence |
|---|---|
| warning | static |

## What it detects

`VACUUM FULL`, `CLUSTER`, non-concurrent `REINDEX`, non-concurrent `REFRESH MATERIALIZED VIEW`, and `ALTER TABLE ... SET TABLESPACE / SET LOGGED / SET UNLOGGED / SET ACCESS METHOD`.

## Why it matters

Each of these rewrites or rebuilds data while holding a lock that blocks traffic (`ACCESS EXCLUSIVE` for most, `SHARE` for `REINDEX TABLE`). The duration scales with data size.

## Example

Flagged:

```sql
REFRESH MATERIALIZED VIEW sales_by_day;
REINDEX TABLE orders;
```

Preferred:

```sql
REFRESH MATERIALIZED VIEW CONCURRENTLY sales_by_day;  -- needs a unique index
REINDEX TABLE CONCURRENTLY orders;
```

## How ProdShadow verifies it

The candidate run measures the blocking period on your fixture.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS113: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS113 reason="why this is acceptable" expires=2027-06-30
```
