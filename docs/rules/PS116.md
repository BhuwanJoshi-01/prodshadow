# PS116 · statement-not-analysed

| Default severity | Evidence |
|---|---|
| inconclusive | experiment quality |

## What it detects

A statement the bundled parser (PostgreSQL 17 grammar, libpg_query) cannot parse.

## Why it matters

Its locks cannot be predicted statically. The statement is still executed in the disposable server, so the observed results remain valid; only the static explanation is missing. Syntax added in newer PostgreSQL versions is the usual cause.

## Example

Flagged:

```sql
-- syntax the bundled grammar does not know yet
```

Preferred:

```yaml
policy:
  rules:
    PS116: info   # rely on observed results for this syntax
```

## How ProdShadow verifies it

Check the candidate run's observed findings; they do not depend on parsing.

## Configuration

Change the severity or turn the rule off in `prodshadow.yaml`:

```yaml
policy:
  rules:
    PS116: critical   # or info, warning, off
```

Suppress a reviewed case next to the statement:

```sql
-- prodshadow:ignore PS116 reason="why this is acceptable" expires=2027-06-30
```
