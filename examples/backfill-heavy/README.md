# Example: heavy backfill

A data migration written as one `UPDATE` without a `WHERE` clause. It takes
only `ROW EXCLUSIVE` on the table, so reads and unrelated DDL are unaffected,
but it locks every row it touches until it commits. Concurrent writes to any
of those rows queue on the backfill's transaction.

```bash
prodshadow verify --config examples/backfill-heavy/prodshadow.yaml
```

**Expected result:** `block` (exit code 2) with `OBS001 lock-wait-budget`
(write sessions wait on transaction locks held by the migration). Static
rule `PS111` flags the unbounded `UPDATE`; the phase counters show the WAL
generated by the backfill.

**What to change:** backfill in bounded batches committed separately, e.g.
`UPDATE ... WHERE id BETWEEN $1 AND $2`, driven by a script outside the
schema migration.
